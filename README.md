# mass_loader

Приложение для **массовой выгрузки данных из умных электросчётчиков** по протоколу DLMS/COSEM с последующим анализом журналов и отправкой уведомлений.

## Стек технологий

- **Python 3.13**
- **PyQt5** — графический интерфейс
- **Gurux DLMS** (gurux-common, gurux-dlms, gurux-net, gurux-serial) — библиотека для DLMS/COSEM
- **openpyxl** — генерация и анализ Excel-отчётов
- **pandas** — обработка данных
- **requests** — API для RSM (Remote System Management)
- **smtplib** — отправка email-уведомлений
- **pywin32** — автоматизация установки драйвера CH340

## Установка

```bash
pip install -r requirements.txt
```

## Запуск

```bash
python main_ui.py
```

## Архитектура

```
main_ui.py (GUI, PyQt5)
│
├── WorkerThread / QTimer — фоновые задачи
│   ├── read_meter_data_task — опрос счётчиков (в 13:10)
│   └── read_log_task — выгрузка журналов (в 13:30)
│
├── libs/connect.py — подключение (COM/IP, авто-скорость)
├── libs/read.py — чтение журналов (~20 типов)
├── libs/log_analysis.py — анализ Excel-данных
├── libs/GXDLMSClient.py — DLMS-клиент (обёртка Gurux)
└── libs/sending_message.py — уведомления (email)
```

## Основные модули

| Модуль | Назначение |
|--------|-----------|
| `read.py` | Чтение 20+ типов журналов (напряжение, ток, качество сети, самодиагностика, профили тарифов) в Excel |
| `connect.py` | Управление подключением (COM-порт/TCP/IP, динамическая скорость 9600→115200) |
| `GXDLMSClient.py` | Обёртка над Gurux: аутентификация, чтение/запись, Profile Generic |
| `log_analysis.py` | Анализ содержимого Excel-журналов |
| `for_restart_driver.py` | Автоматическая переустановка драйвера CH340 через Win32 API |
| `sending_message.py` | Отправка уведомлений на email |

## Настройка email-уведомлений

В `libs/settings.py` укажи свои данные:

```python
SMTP_SERVER = "smtp.mail.ru"
SMTP_PORT = 465
EMAIL_SENDER = "твой_email@mail.ru"
EMAIL_PASSWORD = "пароль_приложения"  # Создай в настройках безопасности Mail.ru
EMAIL_RECEIVER = "твой_email@mail.ru"
```

**Пароль приложения** (Mail.ru):
1. Настройки → Безопасность → Пароли приложений
2. Создать → "Другое"
3. Скопировать пароль → вставить в `settings.py`

## Конфигурация

## Анализ журналов

После выгрузки данных запускается автоматический анализ каждого журнала.

### Типы проверок

| Проверка | Описание |
|----------|----------|
| **Валидность дат** | Поиск невалидных дат (FFF-последовательности) |
| **Хронология** | Проверка что даты идут в правильном порядке |
| **Часы работы** | Счётчик часов работы ИПУ не убывает |
| **Коды ошибок** | Поиск ошибок самодиагностики |
| **Повторы** | Обнаружение повторяющихся событий |
| **Интервал** | Проверка интервала между записями |

### Описание функций анализа

| Функция | Назначение |
|---------|-----------|
| `analysis_correct_date_ref(sheets, log_name)` | Проверяет столбец **"Время фиксации записи"** на наличие невалидных дат (FFF-последовательности) |
| `time_ordering_analysis_ref(sheets, log_name)` | Проверяет хронологический порядок дат — каждая следующая дата ≥ предыдущей |
| `ipu_working_hours_ref(sheets, log_name)` | Проверяет столбец **"Время работы ИПУ"** — счётчик часов работы не убывает |
| `time_ordering_analysis_for_daily_profile(sheets, log_name)` | Проверяет суточный профиль — разница между датами = **1 день** |
| `time_ordering_analysis_for_month_profile(sheets, log_name)` | Проверяет месячный профиль — разница между датами = **1 месяц** |
| `checkForSelfDiagnostics(sheets, log_name)` | Проверяет журнал самодиагностики на наличие кодов ошибок |
| `checking_for_repeated_on_or_offs(sheets, log_name)` | Проверяет журнал включений/выключений на повторяющиеся события |
| `time_ordering_analysis_with_minutes(sheets, log_name, time)` | Проверяет профиль с заданным интервалом (30 или 60 минут) |

### Как работает анализ

1. Открывает Excel-файл через `openpyxl`
2. Находит нужный столбец по названию в заголовке
3. Итерируется по строкам и сравнивает значения
4. При ошибке:
   - Красит ячейку в розовый (`pink_fill`)
   - Выводит сообщение в консоль
   - Добавляет в `global_list` для отправки на email
